# Наглядность и выбор инструментов

## Сначала объясняемый вопрос

Запиши для себя, какое затруднение снимает изображение. Примеры:

| Что трудно понять | Подходящая форма |
| --- | --- |
| Как данные проходят по этапам | Последовательная схема с состоянием данных на каждом шаге |
| Как меняется объект при преобразовании | Соседние состояния или управляемый показ шагов |
| Как формула связана с объектами | Подписи к переменным рядом с соответствующими частями рисунка |
| Почему два решения дают разный результат | Два случая на одинаковой шкале с выделенным различием |
| Что означают размеры тензора | Группы объектов, каналы и оси с конкретными числами |
| Как числовой параметр влияет на поведение | График/симуляция с единицами, исходным случаем и объяснением изменения |
| Как компоненты системы взаимодействуют | Архитектура, последовательность сообщений или поток данных |

Таблица — набор вариантов, не список обязательных визуалов. Для сравнения точных характеристик иногда лучше обычная таблица. Если текста достаточно, не усложняй страницу.

## Проверка полезности интерактива

До реализации должны быть понятны:
1. Вопрос, на который читатель сможет ответить после взаимодействия.
2. Осмысленное действие читателя.
3. Что меняется и что сохраняется.
4. Наблюдаемый результат и его объяснение.

Одного индикатора «порог превышен — ошибка» обычно мало. Лучше показать, как условие изменяет сам механизм или результат. В одобренной главе перестановка областей картинки сохраняет средние цвета и оценки модели; изменение цветов меняет признаки и ответ. Это раскрывает, какую информацию использует модель.

Сохраняй цвет, обозначения, объект и числовую шкалу между состояниями. Подписывай ноль и отрицательные значения. Показывай единицы измерения и смысл осей. Плавность анимации полезна, когда помогает проследить преобразование; управление чтением должно оставаться у человека. Для управляемой последовательности нужны предыдущий/следующий шаг и возможность вернуться к исходному случаю. Учитывай reduced motion.

Для вычислительной схемы показывай реальную формулу учебной модели; для вымышленных сценариев прямо называй данные учебными. Схема, которая вычисляет формулу в JavaScript, не становится запуском ONNX или измерением GPU.

## Инструменты по роли

Проверяй наличие навыков и инструментов в текущей среде; читай их актуальные инструкции перед использованием. Не устанавливай всё перечисленное заранее.

| Работа | Маршрут |
| --- | --- |
| Прочитать PDF, презентацию, документ | Доступные навыки `pdf`, `presentations`, `documents`; извлечение текста плюс осмотр значимых рисунков |
| Разобраться в репозитории | Поиск и чтение кода, документации и примеров; по необходимости безопасный локальный запуск |
| Проверить технические детали | Первичные источники: официальные документации, исходники, статьи авторов |
| Создать HTML-сайт | Доступный навык `sites`, его актуальный процесс реализации и проверки; сохранить запрошенный пользователем способ доставки |
| Показать интерактив прямо в чате | Доступный навык `visualize`, если пользователь выбрал чат или это помогает текущему объяснению |
| Точная схема, матрица, график, вычислительная анимация в HTML | HTML/CSS/SVG/Canvas и подходящие библиотеки; подписи и числа остаются проверяемыми |
| Научный или экспортируемый числовой график | Стандартные средства построения графиков с контролем данных и шкал |
| Предметная растровая иллюстрация | `imagegen` или поиск допустимого изображения, когда реальная иллюстрация помогает понять предмет |
| Редактируемая диаграмма в Figma/FigJam | Соответствующие навыки Figma, если нужна именно эта среда |
| Архитектура или поток в духе Archify | Если Archify доступен и подходит, прочитай его инструкции и используй. Иначе достаточно собственного SVG или другого доступного средства |

Archify: https://github.com/tt-a1i/archify . Это возможный инструмент для архитектурных схем, потоков, последовательностей и состояний. Он не заменяет написание объяснения и не является обязательной зависимостью. При необходимости сверяй текущие возможности по репозиторию. Не подменяй им числовую симуляцию или объяснение матричного вычисления.

Если обязательный инструмент недоступен, назови ограничение и используй подходящий разрешённый вариант. Не обещай вызов инструмента, которого нет. Вызов этого скилла не разрешает самостоятельную публикацию приватных исходников, сообщения людям, работу с платными сервисами или изменения production. Доставку и внешние действия определяет запрос пользователя и действующие инструкции среды.

## Страница как учебное чтение

Объяснение и изображения разрабатываются вместе, но интерфейс не должен задавать искусственную структуру содержания. Начинай с читаемой главы. Навигация, скачивание кода, раскрытие подробностей и вопросы помогают работе с материалом.

Предпочитай типографику и свободное пространство, поддерживающие длительное чтение. Схему можно сделать шире текстовой колонки. Не помещай каждый абзац в карточку и не прячь необходимые определения за вкладкой «глубже».

Для локального автономного HTML держи необходимые стили, код и данные внутри файла либо приложенного пакета; не обещай работу без сети при зависимости от CDN. Поддержи печать, если она полезна для повторения. Не привязывай учебный текст к наличию JavaScript; основные объяснения должны оставаться доступными.

При проверке открой страницу в поддерживаемом браузере. Проверь значимые состояния интерактива, скачиваемые примеры, вопросы и адаптивность. Проверь мобильную ширину и клавиатуру; удостоверись, что подписи и текст читаются. Исправь ошибки вёрстки, затем повтори только затронутые проверки. Если браузерная проверка недоступна, честно сообщи об этом и выполни доступные проверки исходников.
